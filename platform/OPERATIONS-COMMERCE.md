# 商业运营与本地审核

本项目将本地记录、供应商确认和人工运营动作分别记账。Stripe 回调验签后才能确认支付；浏览器返回成功页不代表支付完成。没有商户配置时保留草稿并拒绝创建收款会话。演示数据不代表可售商品。

## 离线管理入口

仅安装环境的主机管理员运行，不提供 HTTP 管理后门。输入 JSON 的 `actorUserId` 必须是数据库首位注册账户的 UUID；每次首次执行都写入不可覆盖的 `operator_audit`；幂等重试返回原操作结果，不重复审计和入账。指定正确的 `DATABASE_PATH`，避免将演示库当作正式库。

```sh
DATABASE_PATH=/absolute/path/production.sqlite pnpm exec tsx scripts/commerce-admin.ts import-plans /absolute/path/plans.json
```

九个命令均限制 JSON 不超过 1 MiB，拒绝未知字段，通过 Zod 验证后在 SQLite 立即事务内执行。字段规范以 `src/server/billing/admin.ts` 导出 schema 为准。下列 UUID 是需要替换的占位符，不可直接用于实际安装。

`--help` 显示用法，`--schema <命令>` 输出 JSON Schema，不读取或修改数据库。跨字段约束仍由运行时 Zod refinement 验证。写操作必须显式提供 `DATABASE_PATH`，并在打开数据库前先验证输入结构。

## 正式套餐

`import-plans` 输入：

```json
{
  "version": 1,
  "actorUserId": "00000000-0000-4000-8000-000000000001",
  "reason": "已人工审核商品价格、额度、服务条款与商户收款配置。",
  "confirmCommercialCatalog": true,
  "plans": [{
    "id": "00000000-0000-4000-8000-000000000002",
    "name": "由运营确定的正式算力包",
    "kind": "credits",
    "priceMinor": 1000,
    "currency": "USD",
    "credits": 100,
    "interval": null,
    "limits": {},
    "active": true
  }]
}
```

金额为币种最小单位。此示例仅说明输入结构，不构成定价建议。订阅 `kind` 为 `subscription`，必须明确 `interval: month|year`。每次导入版本递增；已建订单保存独立快照，不随套餐修改。取消销售应再次导入同 ID 并设 `active:false`。Stripe live key 只能对正式审核快照创建付款会话，演示空间始终不能使用 live key 收款；test key 只用于测试，不产生推荐奖励。

## 推荐注册和渠道权限

`configure-referrals` 输入 `actorUserId`、至少 20 字符的 `reason`、`registrationEnabled`、`rewardsEnabled`、`rewardCredits`、`minimumPaidMinor`、三位大写 `currency`。默认两个开关均关闭。奖励开启时额度必须大于零。

推荐码在注册事务中与新账户关联；仅开启推荐注册时，它才能绕过关闭的普通注册入口。团队邀请仍要求指定邮箱匹配并原子消费。推荐注册不授予推荐人的团队成员权限。每个新用户只能归因一次，不能自荐。规则在注册时冻结，后续调整不追溯改变已归因账户的规则。

奖励仅在归因用户首个满足最低实付金额、币种且 Stripe **live** 已确认的订单发放，使用不可变额度账本与唯一约束去重。退款按累计退款比例向上取整冲正奖励；不透支已预留额度，未能追回的部分登记债务并暂停相关空间新任务。分配模式下退款导致成员额度总和超过余额，也暂停新任务，直到回收未使用分配并人工复核。

`approve-channel` 输入 `actorUserId`、`userId`、`enabled`、`reason`。获批账户仅能查询其推荐汇总与不含被推荐人邮箱/姓名的匿名归因 CSV。现金佣金结算没有配置或实现，不会把内部额度奖励显示成现金佣金。

## 支付风险处理

必须先由运营人员在商户系统核对实际退款、争议和额度使用情况，再运行 `resolve-risks`：

```json
{
  "actorUserId": "00000000-0000-4000-8000-000000000001",
  "workspaceId": "00000000-0000-4000-8000-000000000003",
  "riskIds": ["00000000-0000-4000-8000-000000000004"],
  "reason": "已核对商户事件和空间使用记录，完成此次人工风险处理。",
  "evidenceReference": "merchant-case:reviewed-case-id",
  "confirmedManuallyHandled": true,
  "creditsToRevoke": 0
}
```

命令仅处理指定空间、指定且尚未处理的风险。若仍有其它待审风险，保持暂停。额度冲正不能低于选中记录关联的推荐债务，不能透支余额或预留额度，不能造成分配池超额。先完成必要充值或未使用额度回收，再解除暂停。重复处理被拒绝，不重复扣款。该命令不会调用退款 API，也不会宣称退款已由第三方完成；`evidenceReference` 是运营核对依据，不是系统验证外部成功的凭证。

## 人物与发票边界

人物参考授权保存操作者、素材版本、声明版本与关系；这是使用者自述，不是人脸核验。修改参考素材令声明失效；撤回会使对应认证会话失效。FACE 供应商未配置时认证启动明确拒绝；只有服务器适配器返回真实核验凭据和有效期才可写入 verified。

发票支持抬头、按订单退款后净额申请、本地提交、撤回与历史事件。`pending` 表示本地待处理申请，`delivery:not-sent`、`providerConfigured:false`、`fileUrl:null`。没有开票供应商时不会生成假税务发票。退款后已有申请转 `review-required`；撤回释放订单占用并保留历史，可按剩余净额重新申请。

## 分享媒体

新链接默认 `allowOriginalDownload:false`，浏览者只能取得已存在的 preview/thumbnail。请求 original 会在服务端返回 403；没有预览的视频不能绕过权限读取原片。旧链接迁移保留先前原件授权，创建者可撤销并重建。令牌过期、撤销、项目不可用或资产不属于当前场景时均不可读取。该能力限制原件接口访问，不阻止截图或保存已经公开的预览。

## 套餐限额与每日免费文本次数

`GET /api/v1/entitlements` 返回当前空间生效的限制、资源占用和 `freeTextAssist` 日桶。空间基线为本机部署参数：项目 1000、成员席位 20、品牌 100、人物 100、有效 API key 20、并发 2、每日免费文本次数 0。它们不是原站商业套餐承诺。`standard` 与 `demo` 分别保存，可由 `configure-entitlements` 调整：

```json
{
  "actorUserId": "00000000-0000-4000-8000-000000000001",
  "reason": "已核对本机资源能力和供应商预算，批准此部署的额度规则。",
  "mode": "standard",
  "limits": { "projects": 1000, "seats": 20, "brands": 100, "characters": 100, "apiKeys": 20, "concurrency": 2, "textAssistDailyFreeUnits": 0 }
}
```

生效订阅必须为 `active`、处于有效期内且关联已支付订单，限额读取该订单的冻结快照。多个同时有效订阅按每个已声明字段取最大值；未声明字段沿用部署基线，不做相加。创建/恢复项目品牌、创建人物/API key、发邀请和接受邀请在同一写事务内重新核验。未过期且未消费的邀请占用席位。到期或降级保留已有资源，只拒绝超过限制的新创建，允许读取和删除。

每日免费文本次数以空间为单位，UTC 零点重置，默认禁用。只适用于 `text.assist`，提交时原子领取，重复请求同一 item 不重复计数，失败或取消仍消耗该次尝试。不同于应用额度，也不代表供应商不收费；部署人员应先核对真实供应商成本再开启。配额用尽时须重新报价，不能无限零额度提交。

## 申诉审核与应用额度退回

用户先建立关联具体任务的 `appeal` 工单。离线首位安装管理员人工查看结果和结算证据后运行 `resolve-appeal`，批准输入如下：

```json
{
  "actorUserId": "00000000-0000-4000-8000-000000000001",
  "workspaceId": "00000000-0000-4000-8000-000000000003",
  "ticketId": "00000000-0000-4000-8000-000000000005",
  "decision": "approved",
  "reason": "人工复核指定已结算产物不符合服务约定，批准退回应用额度。",
  "evidenceReference": "support-review:case-id",
  "items": [{ "itemId": "00000000-0000-4000-8000-000000000006", "credits": 10 }]
}
```

驳回使用 `decision:rejected`、`items:[]`。只能审核 open 工单，指定 item 必须属于该空间、该工单的任务，状态 succeeded 且有匹配的 settle 账本。单项不能超过原结算额；每个 item 仅允许一次裁定退回（包括部分退回），不能通过另一工单重复退回。完全相同的命令重试幂等；已裁定工单不允许改写理由或金额。裁定、余额、成员 spent、退款记录、通知与审计在同一事务提交，任何条目失败均回滚。任务原始 settled 数额保留，退回以额外调整账本体现。该命令不退现金，也不向 AI 供应商申请退款。


## 额度来源、有效期、封存与恢复

`GET /api/v1/credits/buckets` 返回当前空间的来源分桶；仍使用 `balance`、`reserved` 的原余额接口。`available = balance - reserved`，等于全部有效来源的可用余额。`remaining` 包含该来源尚未结算的预留；封存和已失效来源只将仍在途的 `reserved` 纳入总余额。所有额度都是此部署的应用预算单位，不代表现金或模型供应商余额。

| 来源 | 期限与续期规则 |
| --- | --- |
| Stripe 会员订阅 `subscription` | 已验签付款入账后使用服务端核验的订阅周期结束时间。到期封存三个 UTC 日历月；新一期核验付款延长尚有效会员来源并恢复仍在封存期的会员来源。清除后的来源不恢复。 |
| Stripe 算力包 `pack` | 从已验签付款事件时间起一年；再次购买延长仍有效的算力包来源，不恢复已失效来源。 |
| 推荐奖励 `referral`、兑换 `redemption`、演示初始 `initial` | 当前部署默认为不自动到期。推荐注册证据没有完整赠送额度有效期规则，因此不冒充原站赠送规则；兑换码的可兑换期限与兑换后额度期限分开。 |
| 人工授予 `manual` | 管理员明确提供 `expiresAt` 与可选 `archiveMonths`（0–12）；默认为无到期。 |
| 迁移旧余额 `legacy` | 缺少可信来源日期，保留迁移时未消耗余额且不推测到期日；`granted` 为迁移期初余额，不是历史累计购买额。 |
| 旧结算退款 `legacy-refund` | 原已结算记录没有来源归属时单独记账并标记期限未知；不制造原始购买日期。 |

在每次读取余额/分桶、预留、结算、退款、授予和续期时于同一 SQLite 写事务检查过期。离线期间无需定时器；重启后的首次操作会完成应有的到期/封存处理。月末和闰日按 UTC 日历计算并夹到对应月最后一天，不按固定 30/365 天估算。有效来源按最近到期优先，同期限按创建顺序 FIFO，永久来源最后；同毫秒创建也保留写入顺序。

到期只移除尚未预留部分，已经提交的在途任务保留来源分配。任务成功仅结算一次；失败或取消释放回原来源，有效来源恢复可用，封存来源回封存，已失效来源清除，不借取消延长有效期。已付费任务的申诉退回同样遵循原来源状态；审核通过数额可能进入封存或已经失效，通知不把它承诺为新可用额度。需要额外补偿时由管理员另行授予新的来源并说明理由。

管理员可用以下命令进行明确的本地运营动作。均须有效安装管理员、至少 20 字符 `reason`、业务唯一且持久的 `eventKey`（1–200 字符）。完全相同输入重试幂等，同键改金额、空间、期限或理由拒绝。它们不调用外部支付或修改真实供应商余额。

```json
{
  "actorUserId": "00000000-0000-4000-8000-000000000001",
  "workspaceId": "00000000-0000-4000-8000-000000000003",
  "userId": "00000000-0000-4000-8000-000000000001",
  "eventKey": "approved-adjustment-case-2027-001",
  "reason": "已人工审核原始来源及服务补偿记录，批准此次新的额度授予。",
  "amount": 100,
  "expiresAt": "2027-12-31T23:59:59.000Z",
  "archiveMonths": 3
}
```

上例用于 `grant-credits`；目标用户必须为该空间成员，到期时间若提供必须在未来。`extend-credits` 和 `restore-credits` 使用 `actorUserId`、`workspaceId`、`lotId`、`eventKey`、`expiresAt`、`reason`，不接受 `amount` 或 `userId`。延期只能延长当前有效且有限期的来源；恢复只能针对尚在封存窗口内的来源。不能借恢复重建已消耗、已清除或跨空间的余额。操作事件、来源变更、总余额与审计同时提交。

迁移 `0013-credit-lots.sql` 以原不可变 reserve/final 事件回填旧在途来源。若旧总预留与事件不一致，迁移整体回滚并报错，需先人工核对旧账；不能通过清空预留绕过。升级后不允许直接 SQL 修改 `credit_accounts`，所有授予/冲正必须走来源服务或上述 CLI，否则会破坏账本一致性。
