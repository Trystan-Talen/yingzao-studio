# 映造 Studio

面向电商图片与视频创作的应用。业务和文件真实保存，数据库继续使用 SQLite（嵌入式数据库）。2026-10-26 商业质量审查与修复见[本轮交付](../reviews/commercial-20261026/DELIVERY.md)，发布前检查见[发布与恢复操作](OPERATIONS-RELEASE.md)。[接手状态](../reviews/takeover/STATUS.md)与[逐项范围台账](../reviews/takeover/scope-ledger.json)保留功能范围和外部未验证项；旧交付材料不能代替当前版本验收。外部模型效果和运营服务尚未全部验证。

## 前端交互的隔离体验

运行 `pnpm dev:experience`，按终端提供的地址打开（默认53820）。测试账号 `preview@example.local`，密码 `PreviewStudio2026!`。图片、视频、详情页的外部服务全部由本机模拟替代；会创建真实可预览的文件和独立数据库，但不产生真实模型费用。

端口占用时可使用 `pnpm dev:experience --port 53826 --api-port 53827`。每次启动使用新目录并保留旧目录；此入口只用于交互验收，不能用于真实创作。原有用户数据、模型配置与正式启动方式保持独立。

## 本机快速体验

macOS 可直接双击项目上一级目录中的 **`启动映造.command`**，自动检查依赖、启动前端/API/任务服务并打开浏览器。已有服务正常运行时会直接复用。请保持启动窗口打开；按 Ctrl+C 或关闭窗口可停止本次启动的服务，SQLite 数据会保留。

需要 Node.js（运行时）22.12 至 22.x 或 24 以上版本、pnpm（包管理器）11，以及视频处理用的 FFmpeg/ffprobe（媒体处理工具）。本轮本机使用 22.23.1、11.25.0；准确支持范围以 `package.json` 为准。默认前端 **5174**、接口服务 **4310**。

```sh
cd platform
pnpm install --frozen-lockfile
pnpm seed-demo
pnpm seed-demo-assets
pnpm dev:demo
```

打开 <http://127.0.0.1:5174>。演示账户：`demo@example.local`，密码：`DemoStudio2026!`。演示数据独立保存在 `var/demo.sqlite` 与 `var/demo-media`，上述种子可重复运行。页面中的八张原创灵感是明确标记的示例，不是应用已调用模型生成的结果。演示额度是本地测试预算，不是现金或外部供应商余额。

`pnpm dev:demo` 同时启动 API、任务 worker 与前端；Ctrl+C 关闭这三个进程。前端与 API 支持开发热更新，worker 代码变更后需重启命令。

上述种子与演示启动只用于演示数据。对已有用户库先做一致性备份，不运行种子来修复问题。`scripts/dev.ts` 会选择自己的数据路径；验证恢复副本或自定义隔离目录时，直接以明确的 `DATABASE_PATH`、`STORAGE_DIR` 启动 `node --import tsx src/server/main.ts` 与 `node --import tsx src/worker/main.ts`，不要经演示启动器覆盖路径。

## 使用自己的数据与模型

```sh
cp .env.example .env
pnpm dev
```

保持 `DEMO_MODE=false`，首次从本机浏览器注册管理员，默认使用 `var/app.sqlite` 和 `var/media`。之后的注册遵循邀请或管理员启用的推荐规则。空间之间独立隔离。默认没有现金订单、模型密钥、赠送额度或伪造任务结果。

### 创作记忆、品牌与产品资料

「设置 → 创作记忆」保存当前用户在当前空间明确确认的信息。长期背景不自动衰减；创作偏好默认90天半衰，权重低于四分之一后不再默认带入；临时要求必须设置未来的到期时间。读取不会刷新确认时间，同主题同用途应编辑原记录。支持停用、重新确认、替换和删除；不会从历史对话自动推断画像。

沿用已有「品牌」，新增「产品库」，可保存产品描述、事实、使用限制、最多四张参考图及关联品牌。产品可以仅自己可见或空间共享，共享产品不能关联私有品牌；只有创建者可以将共享产品设为私有。包含价格或促销等阶段资料时设置有效期。编辑检查版本；发生冲突时可核对最新版，明确载入或合并后再次保存，不自动覆盖。回收中的资料可先修复失效关联再恢复。

图片／视频创作的「更多创作设置 → 更多偏好」可选择品牌、产品并开关个人记忆。产品默认只带入文字，勾选「带入产品参考图」才加入图片；与本次素材共同受模型数量上限约束。个人记忆最多选8条、主题与正文合计6000字，优先有效临时要求、创作偏好、长期背景；同主题优先当前媒体的专属记录。当前明确要求始终优先，个人职业等不能作为商品事实来源。

整理和确认创作时展开「本次采用的资料」核对实际引用、版本和期限。后续追问及执行使用该次快照，新方案才读取新版；过期或衰减失效的旧资料不能产生新报价。已报价任务仍按原方案执行。停用、删除不会擦除历史已确认方案，采用的信息可能体现在协作成员可见的方案和作品中。资料管理与记忆保存本身不调用模型；生成仍按既有流程计费。

已整理的方案可点击「按最新资料重新整理」，保留原话与素材选择，刷新当前空间的资料并取消当前界面对旧报价的复用。再次点击生成才重新规划，可能产生策划费用；旧补充回答需要重新确认。提交中或结果未确认时先核对原请求，不能用重新整理绕过恢复流程。品牌编辑也会核对读取时的版本；遇到并发修改可明确载入或逐字段合并，迟到的保存响应不会清空后续输入。

本轮覆盖单项图片／视频主创作；分组套图、独立工具与整套详情页不接受新资料关联字段。分组模式明确关闭记忆，但草稿保留单项原选择；已选产品须主动取消关联后才能按原流程创作，避免未经规划的模块文案绕过确认。原生规划已接通；使用远端 Dify（工作流编排平台）旧版流程时，需重新导入本项目更新的工作流包。第0040号迁移追加资料表，第0041号追加规划连接版本字段；首次将新版本用于已有运行库前，仍须完成下文的在线备份、媒体校验和恢复检查。见[设计方案](../reviews/creative-memory-20261113/PLAN.md)、[首次交付验收](../reviews/creative-memory-20261113/DELIVERY.md)和[后续复查](../reviews/creative-memory-recheck-20261114/REVIEW.md)。

### 原生图片与视频编排

空间创建者或管理员进入「设置 → 模型配置」，分别配置文本、图片、视频服务。三个槽位可以使用同一中转站，也可以连接不同站点。初始均未启用、未指定模型；先填写地址与密钥，点击「保存并刷新模型」，再选择模型并启用。没有模型目录的服务可以手动填写准确模型标识；目录中的名称不会自动判定为图片或视频模型。

默认地址采用星云引力，模型与权限仍须以自己的中转账户为准：

| 类型 | 已接入协议                                                          | 默认服务地址与请求路径                                                                                                              |
| ---- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 文本 | `openai-chat`（对话补全兼容协议）                                   | `https://xingyunyinli.com/v1`；请求 `/chat/completions`（对话补全路径）                                                             |
| 图片 | `openai-images`（图像兼容协议）或 `seedream-images`（豆包图像协议） | `https://xingyunyinli.com/v1`；请求 `/images/generations`（图片生成路径），兼容协议的参考图编辑使用 `/images/edits`（图片编辑路径） |
| 视频 | `seedance-native`（豆包原生任务协议）                               | `https://xingyunyinli.com/doubao/api/v3/contents/generations/tasks`；向完整任务地址提交并按返回编号查询                             |

星云引力的文本、图片地址仅填站点根目录时会补为 `/v1`（第一版接口路径）；其他服务须填准确的接口基础地址。文本、图片默认从基础地址下的 `/models`（模型目录路径）读取目录；视频目录单独配置，默认 `https://xingyunyinli.com/v1/models`。目录地址必须与服务地址同源。密钥由后端加密保存，留空保留原密钥；更换站点时须重新填写。

真实生成请双击项目根目录的 `启动真实生成.command`（真实模式启动器），默认打开 [5176端口入口](http://127.0.0.1:5176/)，并设置 `DEMO_MODE=false`（关闭演示模式），具体见文末说明。命令行开发也可在 `platform`（应用目录）执行 `DEMO_MODE=false pnpm dev`。`启动映造.command`（原演示启动器）和 `pnpm dev:demo`（演示启动命令）使用演示库，不执行自定义模型生成。指定隔离数据路径时，按上文直接启动服务端与任务执行器；两者必须使用同一数据库、媒体目录及加密密钥。视频还要求服务端与执行器都能找到 `ffmpeg`（媒体处理程序）和 `ffprobe`（媒体探测程序），缺失时会在文本规划前阻止视频生成。

先准备平台额度，再开始创作：真实新空间默认余额为零。本机安装管理员打开「用量与订单 → 增加测试额度」，输入积分并确认，即可为当前空间直接增加内部网页预算，单次最多100000积分。网页操作即可完成，兑换码作为备用方式保留。此入口仅限本机开发部署的安装管理员，其他空间管理员、开放接口密钥及公网生产部署不可使用。请求支持防重复与审计，不产生人民币订单、不充值中转账户。新原生规划会先核对媒体生成所需积分与成员额度，余额不足时不会调用文本模型；读取已经保存的规划结果不收费。

备用兑换方式：对**明确选择的数据库**运行 `DATABASE_PATH=var/app.sqlite DEMO_MODE=false pnpm create-redemption 100`（创建100平台额度的一次性兑换码），随后在「用量与订单 → 兑换额度」入账；自定义数据路径须替换为实际路径。该操作只分配本部署的内部预算，不增加中转账户余额。已有运行库执行管理命令前须按下文完成备份。

图片流程为「文本规划并确认 → 图片生成」。视频先规划首帧与运镜：同画幅、无需改动场景与主体的参考图可以直接作为首帧；需要新画面时才调用图片模型，再由视频模型生成成片。具体选择写入确认摘要，不依赖 Dify（工作流编排平台）。首帧校验并持久保存；同输入、同配置、同重试来源才能复用。图片报价8平台积分；视频每秒5积分，需要重新生首帧时另加8积分。5秒原图首帧视频25积分，新首帧33积分；原图候选通过服务端尺寸与权限检查后，规划最低门槛为25积分，最终报价仍以确认方案为准。文字规划和真实模型费用由中转服务结算，平台积分不是人民币报价。配置变化后须重新确认方案；提交结果不明时保留待核对状态，不自动重复付费提交。

已确认的视频分阶段提示词会保存为服务端快照，后续报价和恢复沿用快照。图片验收以原始请求的像素尺寸核对实际文件；低分辨率、错误画幅或缺少可信请求规格的旧缓存进入待核对，保留原件且不结算为成功。生成的视频首帧也须先通过尺寸和完整解码检查，才会提交视频。规格不符时恢复仅检查已有结果，不重新生成。

当前每次生成一张图片或一段视频，最多四张图片参考；视频支持5秒或10秒、720p（高清），不提供字幕叠加、用户尾帧上传或音轨生成。已核实的 Seedance 2.0（豆包视频模型）还支持静态商品的微小水平运镜：原图首帧配合本机构造的1%–3%位移尾帧，引导视频模型连接两帧。主体只做整数平移，外侧少量背景镜像延展；有贴边主体、文字或明显边缘线条的参考不宜采用，确认时须检查。摘要会说明边缘延展，中段形状和运镜仍需看成片，不能把首尾约束当作像素保真保证。明确的环绕、主体动作等不套用此控制。2.0系列的方形720p对应960×960像素，其他画幅按官方尺寸表校验。具体图片比例与清晰度由所选协议限制，未知中转别名不自动开启已核实模型的端点控制；目录成功也不能证明生成质量。

### 既有生成服务

在「设置 → 生成服务」配置该空间的 OpenAI / fal / Flyelep（模型供应商）或 Tikhub（视频链接解析供应商）密钥，或在 `.env` 配置安装级密钥；工作空间配置优先。这些是独立的既有适配器，不会自动填充上面的三个原生模型槽位。密钥保存在后端，经 AES-256-GCM（认证加密算法）加密，前端只能看到末尾提示。模型可用性由实际适配能力和密钥共同决定；“已连接”不代表外部生成质量已验收。

- OpenAI：图片生成/编辑、白底与电商物料、局部重绘、图片翻译、OCR、文案帮写等。
- fal：Wan 视频生成、Kling 首尾帧和多参考生成、视频编辑、延长/放大/口播翻译、抠图、4×放大和透明图层拆分。具体模型约束显示在表单中。
- Flyelep：已按公开 API 文档实现相应图片任务；引用素材时需要外部可访问的 HTTPS `PUBLIC_ORIGIN`。
- 本机：真实图片缩放、格式转换、长图拼接、视频裁剪；不依赖外部模型。
- 抖音与国际版抖音链接：通过明确配置的解析供应商导入视频，另行确认内容授权及解析费用；解析成功但媒体下载失败也可能收费。小红书解析缺少可核验服务合同，当前明确拒绝，用户可上传有权使用的文件。

创作草稿按用户、空间、项目、图片/视频分别保留；提交结果未知时先点“核对提交结果”，避免再次调用模型。进入画布默认收起创作区，可展开找回需求；画布自动保存、历史版本和创作草稿分别记录。生成产物可在作品区查看、对比或作为参考继续创作。

所有外部模型的合同测试与真实联调分别记录。已有少量授权真实调用，其通过范围、失败与产物质量问题见[当前状态](../reviews/takeover/STATUS.md)；不能据此认为所有模型或商品均已通过。本轮前端体验重构只用隔离模拟验证交互，没有追加收费调用，见[交付记录](../reviews/frontend-rebuild-20261030/DELIVERY.md)。配置真实密钥后提交会请求相应供应商，费用以供应商为准；应用显示的额度是部署者制定的内部预算单位。

## 支付、额度与正式运营配置

Stripe Checkout、订阅和签名 Webhook 已实现。需要同时配置 `STRIPE_SECRET_KEY` 与 `STRIPE_WEBHOOK_SECRET`，回调地址为 `/api/v1/billing/stripe/webhook`。只以服务端验签的付款事件入账，浏览器跳转不能将订单变成已付款。演示模式仅接受 Stripe 测试密钥，真实付款只允许正式批准的套餐。事件、重复回调、退款及争议保留审计；争议冻结后续付费任务，需要运维人工核对解除。

额度按来源和有效期分桶；会员到期封存、有效续费恢复、额度包延长和原来源退款有独立审计。无文字图片翻译保留原件并释放平台预留，可选强制翻译；文字预检本身可能产生供应商费用。导出水印通过 `EXPORT_WATERMARK_MODE=off|all|non-subscribers` 配置，会员豁免由服务端当前订阅决定，演示空间豁免。水印作用于应用导出，不是防止修改客户端的保护措施。

网页与开放接口使用独立额度账户：旧余额保留在网页渠道，接口渠道从 0 开始，不能因网页有余额就视为接口可用。新增固定期会员、活动价格及推荐规则必须显式配置并批准；当前规则、迁移冻结状态和外部未验范围见本轮状态，不复制原站价格作为本部署承诺。测试与正式支付须使用不同数据库，启用支付后的环境绑定用于防止测试付款污染正式权益。

已经由验签回调绑定的 Stripe 订阅订单可查看服务商账单及 PDF；它是支付账单，不代表本地税务发票已开具。

管理员可用 `DATABASE_PATH=/已选择的数据库路径 pnpm create-redemption <额度>` 创建一次性本地额度兑换码；缺少非空数据库路径时拒绝执行，不回落到默认用户库。正式套餐、推荐计划、权益、申诉及支付风险管理使用 `pnpm exec tsx scripts/commerce-admin.ts --help`，完整命令、输入 schema（结构合同）与流程见 [OPERATIONS-COMMERCE.md](OPERATIONS-COMMERCE.md)。管理命令要求显式选择 `DATABASE_PATH`（数据库路径）。这些命令只适用于管理自己的部署，不能修改外部供应商余额。

正式税务开票尚无服务商适配及可核验协议，本地申请记录不能代替开票。短信/微信登录已接通协议、账户流程及隔离测试，默认关闭，配置与未完成的真实服务验收见 [身份服务运维](OPERATIONS-IDENTITY.md)。普通人物参考的自述授权记录不能替代身份核验。

帮助页的本实例客服与外部问卷在环境配置中设置：`SUPPORT_PHONE`（联系电话）、`SUPPORT_HOURS`（服务时间）、`SUPPORT_WECHAT_QR_URL`（微信二维码图片）、`SUPPORT_FEEDBACK_URL`（反馈问卷）、`SUPPORT_GUIDE_URL`（使用指南）。默认留空并显示未配置，不使用原站联系方式。链接必须使用不含账户凭据的加密网页地址；这些字段会展示给登录用户，不可填入秘密。二维码只在用户点击查看后加载，问卷在新标签页打开；本地工单仍是独立记录，不代表已联系外部客服。

Google OIDC 登录和显式账户关联已实现，默认关闭，配置与真实联调步骤见 [OPERATIONS-GOOGLE.md](OPERATIONS-GOOGLE.md)。不会自动把同邮箱的 Google 身份并入本地账户；Google-only 账户不能解除唯一登录方式。

密码找回和仅谷歌账户设置本地密码见 [密码服务运维](OPERATIONS-PASSWORD.md)。找回默认关闭，使用一次性令牌与加密邮件队列；敏感修改会撤销旧会话。安装管理员在第 0027 号迁移后固定为不可变记录，不再随用户创建时间或编号排序改变；旧库的首用户推导来源保留标记。

SMTP 持久邮件队列已实现，默认关闭；实际邀请、工单回复与站内通知在来源事务内入队，由独立 worker 投递。状态页区分排队、SMTP 接受、失败与待核对；接受不等于最终送达。配置、重试和人工核对见 [OPERATIONS-MAIL.md](OPERATIONS-MAIL.md)。本轮只用本机假 SMTP 验证，没有真实外发。

## 构建与运行

依赖状态不一致时，pnpm（包管理器）会明确报错，不在运行检查时自动安装。需要修复依赖时显式运行安装命令；日常统一使用 `pnpm quality:check`（开发质量检查），构建验收使用 `pnpm quality:release`（构建质量检查），具体约束见[工程质量规范](QUALITY.md)。也可直接运行 `node --import tsx scripts/quality.ts`（质量入口）或 `node --import tsx scripts/test.ts`（隔离单元入口）。不要用裸测试运行器绕过父进程凭据和数据路径清洗。

```sh
pnpm quality:check
pnpm quality:release
# 界面变更另运行相关桌面／手机验收；不传筛选参数则运行完整浏览器集
pnpm test:e2e
# 两个终端分别启动；均在 platform 目录执行
NODE_ENV=production pnpm start
NODE_ENV=production pnpm start:worker
```

生产环境必须设置独立高熵 `SESSION_SECRET`（签名密钥）、`ENCRYPTION_KEY`（加密密钥），每项至少32字节，禁止 `DEMO_MODE=true`（演示模式）。既有安装不得直接更换加密密钥，否则已存凭据无法解密。`PUBLIC_ORIGIN`（公开源站）只接受不含凭据、路径、查询与片段的 HTTP/HTTPS（网页协议）源站，公网生产必须使用 HTTPS（加密网页协议）。接口进程同时服务 `dist/web`（前端构建）。本机可使用回环地址验收构建。公网部署需要正确的反向代理与 FFmpeg（媒体处理工具），本交付没有自动发布到公网。

数据库迁移在 API/worker 启动时自动执行，也可执行 `pnpm migrate`。迁移有校验和与事务锁；不要改动已经应用的 SQL 文件，新增后续迁移。两进程同启、迁移冲突、幂等与恢复均有回归测试。

## 数据备份与恢复

```sh
pnpm backup
# 演示数据库必须显式指定路径，避免现有环境配置指向其他库
DATABASE_PATH=var/demo.sqlite STORAGE_DIR=var/demo-media DEMO_MODE=true pnpm backup
pnpm restore /完整/备份目录 /新的/恢复目录
```

备份包含 SQLite（嵌入式数据库）在线一致性快照、原件与预览、密钥及逐文件 SHA-256（内容摘要）清单。新备份在暂存目录完成资产和在途任务缓存核验后才发布；拒绝符号链接、覆盖目标、源库缺失及媒体目录内的备份目标。恢复校验全部文件摘要、数据库完整性、外键、媒体大小和原件摘要，再将有效任务缓存重定位到恢复目录。旧版备份仍支持数据库及原件核验，但原先没有的预览/密钥摘要无法追溯补证。缓存清单损坏、归属不匹配或文件缺失时拒绝发布新备份或恢复，需保留源备份另行核对，绝不读取旧运行目录或重新付费提交。

停止目标实例后，将 `DATABASE_PATH`（数据库路径）、`STORAGE_DIR`（媒体目录）和恢复目录 `keys.json`（密钥文件）中的原密钥配置到新实例。恢复会修正副本中的缓存路径，源备份保持不变。备份含私有媒体与解密密钥，应保存在受限目录和独立备份介质中；不要提交 `var`（运行数据）、`.env`（环境配置）或备份。

## 代码结构与约束

- `src/contracts`：Zod 输入/数据契约、能力枚举、画布模型。
- `src/web`：React 页面、公共交互、三语字典与 Fabric 编辑器。
- `src/server/core`：身份、空间权限、文件、项目/版本、素材、团队、商业与分享业务。
- `src/server/tasks`：报价、预算、持久队列、恢复、事件流与待应用结果。
- `src/server/providers`：按真实协议分离的模型与本地处理适配器。
- `src/server/billing`：Stripe、回调幂等、套餐与支付风险管理。
- `src/server/auth/google`：OIDC 发现、PKCE/JWKS、一次性流程及账户关联。
- `src/server/auth/password`、`src/server/auth/identity`：一次性密码恢复、短信挑战、微信关联与独立加密发送队列。
- `src/server/notifications`：加密 outbox、SMTP 投递、来源复核与退避恢复。
- `src/worker`：独立执行器，租约与 fencing 防止旧进程重复回写。
- `migrations`：只追加的 SQLite 迁移；`scripts`：种子、启动、备份与管理命令。
- `tests`：隔离临时数据库、真实文件处理与显式外部服务协议夹具。

TypeScript 严格模式，服务端重复校验权限和输入。异步结果记录画布版本，发生冲突时进入待应用区；不能覆盖用户正在编辑的内容。任务报价一次性消费，成功项结算、失败项释放，未知外部状态保留待核对，不盲目重提。

登录后可在 `/api/docs` 查看 OpenAPI；API Key 支持空间和权限范围、到期/撤销、额度上限。健康检查使用 `pnpm health`，只读取主机与端口并检查接口，不生成安装密钥或打开数据库；自定义实例通过 `HOST`（主机）、`PORT`（端口）选择。

`pnpm verify:runtime` 使用临时数据库、随机端口和临时密钥启动实际构建产物，检查 HTML/JS、首次注册、生产 Cookie、API/worker 共同迁移，并关闭进程和清理临时数据。它不会读取模型密钥、调用供应商或修改演示数据库。`pnpm test` 的合同夹具也不是实际模型效果证明。

浏览器验收执行 `pnpm test:e2e`。首次需要将测试浏览器安装到独立目录：`PLAYWRIGHT_BROWSERS_PATH=var/tools/playwright pnpm exec playwright install chromium`，并确保媒体工具在命令搜索路径中。脚本先构建，再为每个用例建立临时数据库、媒体与本机端口，阻止浏览器外网请求，报告保存在忽略的 `var/e2e/`。失败追踪可能含隔离测试会话；公开证据只归档审阅过的报告、诊断和虚构样本截图，不提交配置、数据库或私有媒体。

## 本机真实生成入口

在项目根目录双击 `启动真实生成.command`（真实模式启动器），访问 [真实生成入口](http://127.0.0.1:5176/settings?tab=models)。它使用5176前端端口与4316服务端端口，直接启动服务端和执行器，固定使用本项目 `var/app.sqlite`（真实数据库）及 `var/media`（真实媒体目录）；原演示入口与演示数据保持独立。

首次注册本地账户后，安装管理员先在「用量与订单 → 增加测试额度」为当前空间增加内部积分，再到「设置 → 模型配置」保存并启用所需服务。真实空间积分和外部模型余额分别准备；点击增加测试额度只调整本项目预算。启动器不会自动加积分、充值或创建生成任务。没有云端模型密钥也能启动；依赖须预先安装。协议接入与本机测试不能代替真实成品验收，图片、视频各自的最新实测结论以[接手状态](../reviews/takeover/STATUS.md)为准。

启动器将缺失的签名与供应商加密密钥生成到被忽略的 `var/real-mode/local-config.json`（本机私密配置），文件仅当前用户可读写。已有本机配置优先，原环境文件不会覆盖；既有真实数据库会优先沿用原密钥，缺少原密钥时拒绝生成替代值。请保留并备份该配置，不能删除后重新生成，否则已保存的供应商密钥可能无法解密。`PROVIDER_ENCRYPTION_KEY`（供应商加密密钥）在启动时映射为应用读取的 `ENCRYPTION_KEY`（加密密钥）。

媒体工具优先从 `var/tools/native-media/bin`（本机媒体工具目录）查找。关闭启动窗口或按停止快捷键结束本次进程；终端可追加 `--no-browser`（不打开浏览器）或 `--check`（仅检查配置，不打开数据库、不启动服务）。这些选项仍会在首次使用时创建私密配置。
