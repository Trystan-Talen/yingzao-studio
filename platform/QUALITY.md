# 工程质量与维护规范

应用根目录是本目录；当前实现与验收范围以[接手状态](../reviews/takeover/STATUS.md)和[功能台账](../reviews/takeover/scope-ledger.json)为准。本文件规定后续改动应如何检查，不替代实际验收记录。

## 常用检查

在应用目录执行：

```sh
pnpm quality:check
pnpm quality:release
pnpm test -- tests/knowledge.test.ts
pnpm test:e2e -- knowledge-refresh.spec.ts --project=desktop --project=mobile
```

- `quality:check`（开发质量检查）：依次执行严格类型、代码规范、格式及完整单元／集成测试，任一失败立即停止。
- `quality:release`（构建质量检查）：在上述检查后执行前后端生产构建、本机处理资源复制，以及临时数据库上的生产启动检查。会更新 `dist/`（构建产物），不会启动或更新正式实例；**不代表已经部署，也不包含浏览器验收。**
- `test`（单元测试）：通过隔离入口运行，支持原有文件和名称筛选；不要用裸测试运行器替代它。
- `test:e2e`（浏览器验收）：每个用例使用隔离数据库、媒体和本机服务。交互改动必须检查数据及产物，不能只断言页面可打开。

质量记录写入忽略的 `var/quality/`（质量检查目录），浏览器记录写入 `var/e2e/`（浏览器检查目录）。缺依赖应明确失败，先按锁文件安装；检查命令不会联网自动重装工具。

检查进程只继承必要系统环境，不继承数据库路径、模型／支付／通知凭据、节点注入选项或前端构建变量。构建检查也禁用本地环境文件加载。中断保留非零结果，不继续后面的步骤；类Unix系统会清理所属工具进程组，本轮在macOS（苹果桌面系统）验证。Windows（视窗系统）只终止直接子进程，未承诺整棵子进程树清理。需要本机回环监听权限和已安装的媒体／浏览器工具；环境拦截必须与产品失败分开记录。

## 模块与类型

| 目录 | 责任与依赖 |
| --- | --- |
| `src/contracts`（共享合同） | 输入校验、传输结构和纯规则；不依赖界面、服务实现或节点运行时 |
| `src/web`（浏览器界面） | 界面与交互；通过共享合同和接口访问业务，不导入数据库或服务实现 |
| `src/server/core`（基础业务） | 权限、空间、资源和事务规则；不依赖界面 |
| `src/server/tasks`（任务业务） | 规划、报价、预算、队列及恢复；明确保存确认时的执行快照 |
| `src/server/providers`（供应商适配） | 外部协议和本机处理，统一结果与错误，不把未确认状态当失败重提 |
| `src/worker`（任务执行器） | 调度、租约、执行与收尾；不能依赖浏览器状态 |
| `scripts`（运维和检查脚本） | 显式的数据目标、可退出的进程及受控副作用 |

保留严格类型和索引检查；不通过关闭规则、忽略类型或扩大任意类型来消除错误。只用于类型的导入显式标为 `import type`（类型导入）。代码规范检查约束静态跨层导入，测试夹具允许使用节点运行时。共享合同新增字段应考虑旧客户端、历史数据及持久快照的兼容。

大文件本身不是失败条件。新增功能应优先把纯规则、协议转换和独立状态逻辑放入既有模块；拆分时维持行为并用相关回归证明。大型创作组件和执行器仍需渐进维护，不为行数指标进行整块重写。

## 写入、异步与错误

- 先校验权限、空间归属和输入，再进入写事务；跨记录业务修改在同一事务中完成。数据库迁移只追加，不编辑历史迁移。
- 编辑表单区分“已提交快照”和“当前草稿”。迟到成功只能更新对应状态，不能关闭其他编辑器、清空后续输入或覆盖新版本；并发冲突保留本地内容并要求明确核对。
- 异步任务的初始化、执行及清理都必须有错误归属。执行器开启基于类型的未处理异步检查；任务调度不重入，停止时等待领取中的调度和正在执行的工作，最后关闭数据库。
- 付费调用未知结果必须核对原请求，不自动创建新请求。请求标识、已确认规划和报价快照不能因界面刷新被静默重建。
- 失败信息应有可识别的状态和恢复途径；日志不写凭据、原始私有媒体或完整供应商请求。健康检查应只读，写入管理命令必须明确选择目标库。

## 回归与交付

修复可复现缺陷时，先保留失败条件，再断言用户可见行为、持久状态或资源清理。不要只检查实现细节或用模拟服务成功替代真实外部效果。提交的测试不得残留 `only`（仅运行指定测试）；通过命令行筛选，避免静默跳过其余用例。

后端与共用基础设施改动运行完整单元／集成检查；界面改动运行对应桌面、手机浏览器链路；运行脚本、资源路径或打包改动追加生产构建与隔离启动。检查通过后只有新增修改、失败或未解决风险才扩大／重复测试。最终源码与测试版本应核对，分阶段测试分别说明，不把重复用例相加冒充全量。

外部模型、支付和消息联调需要对应授权；纯质量检查不产生这些费用。正式数据修改前完成在线备份、媒体验证与恢复检查。不要提交运行库、密钥、登录态、私有媒体、追踪原件或本地临时配置。交付说明应写清修复、验证范围、仍未验证的能力和部署状态。
