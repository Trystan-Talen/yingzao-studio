映造商品详情页策划，版本 detail-page-v1（第一版）

交付边界
本目录包含可导入的 detail-page-v1.ifpkg（应用包）、同内容 YAML（工作流定义）、四个独立提示词和纯 Python（代码节点）源文件。这里只完成本地合同校验；云端导入、发布和真实模型效果须另行验证。Dify（编排平台）仅策划，不生成媒体、不报价、不确认、不创建资产编号，也不声称已分析图片。

输入与输出
原调用仍只传 brief（文字简报），进入原单次创作策划分支，plan_json（计划字符串）保持旧合同。
新调用额外传 planning_mode=detail-page（详情页模式）、screen_count（屏数，2–10，默认6）、ratio（比例，3:4、2:3或9:16）。简报最多5000字符。输出仍名为 plan_json，内容为 {type:detail-page-plan,version:1,plan}（详情页结构化计划），与 src/contracts/detail-page.ts（共享契约）一致。
本机适配器将结构化方案持久化，用户确认后才报价并提交整套图片。后续实际参考图及各屏统一视觉由图像执行器承接。

节点与调用次数
共18节点，条件分支互斥，原15节点编号保留。旧分支1次模型请求；详情页分支3次：事实/未知提取 → 引文溯源校验与全套视觉规范 → 视觉结构校验与完整逐屏文案/画面提示词 → 合并与安全校验。意图分支1次模型请求：结构化请求构建 → 需求理解 → 事实来源与状态校验。三条已解析字符串经变量聚合器进入唯一结束节点，只声明一次 plan_json（计划输出）。不是将三条创意方向扩写成六屏。
沿用既有 HTTP（网络请求）节点和 Kimi（文本模型），不依赖额外模型插件。环境变量 PLANNER_BASE_URL（基础地址）默认 https://xingyunyinli.com/v1；PLANNER_MODEL（模型）固定 kimi-k3；PLANNER_API_KEY（密钥）公开包留空。每次请求 system/user（系统/用户消息）分离，stream=false（模型非流式），令牌上限分别2048、2048、8192；HTTP连接/读取/写入限10/120/10秒，SSL（证书校验）开启，重试关闭。上限不是费用报价，实测前须另行核价授权。

意图理解增量（2026-11-03）
planning_mode=intent（意图理解模式）同时传 brief（用户原话，最多12000字符）和 intent_request_json（结构化请求，序列化后最多120000个UTF-16编码单元）。合同来自 src/contracts/creative-intent.ts（共享需求合同）：原话、来源文本、前序摘要、用户回复、素材元数据、已选上下文与有范围的策略。原话必须与请求匹配；素材名不是已识别的图像事实。旧模式仍限8000字符、详情页限5000字符，未放宽旧分支合同。
意图结果为 type=intent-plan（需求理解结果），ready（需求已足够）或 needs_clarification（待关键补充）。最多2个问题；通用创意不强加品牌、材质或商品参考图。模型不得静默改变已明确的平台用途；通用平台/用途可据原话识别。事实引文须逐字存在于指定来源，来源编号不可重复；就绪的实物参考模式必须有图片且实际能力支持参考图。就绪仅允许应用继续报价确认，绝不代表授权付费。提示词供应用进一步按平台规则与能力编译，不负责执行。
新分支使用原模型与原环境变量，输出上限8192令牌，无自动重试。本机 analyzeDifyIntent（意图分析辅助函数）使用同应用的阻塞运行接口，总等待上限160秒，为节点10/120/10秒连接/读取/写入及工作流返回留出余量；浏览器上限175秒，两者引用 src/contracts/creative-intent-timing.ts（共享时间边界）。不返回服务商错误原文，不以超时推断未收费。该余量修复外层提前断开，仍不能恢复真正断网或未知运行编号。新Python（代码节点）字段长度按当前Zod 4.6（合同校验库）的Unicode码点规则匹配；序列化输入与输出单独有界。结构化样本通过只证明合同与校验，不证明真实模型必然正确识别意图、不会误解资料或生成高质量媒体。
真实浏览器回归发现：模型返回合法 ready（就绪）内容但省略 questions（问题列表），导致结构校验失败。现在仅在 status=ready（状态为就绪）且 questions 字段不存在时规范为 []（空数组）；不修改其他内容，不接受空值、错误类型、未知字段或其他缺失字段，needs_clarification（待澄清）仍必须有有效问题。Python（工作流节点）与共享前后端合同使用相同条件。该修复不证明模型对就绪状态的语义判断必然正确。原运行失败状态不会因离线回放通过而自动变为成功。
阻塞接口明确返回 failed/stopped（失败/停止），或已验证 succeeded（成功）但输出未通过严格结构与来源校验时，适配器报告确定失败，允许应用提供用户显式重新检查入口；再次检查可能计费。running（运行中）、连接中断或无法识别的外层返回仍为结果待核对，不自动重复提交。所有分支都不执行自动重试。

校验与限制
事实必须逐字来自本次用户原文；来源外商品信息列 unknowns（未知项）。事实阶段与视觉阶段各最多12条未知项，最终按首次出现顺序精确去重，合并最多24条；不截断，不擅自把不同表述当作相同信息。不允许节点补写品牌、成分、功效、认证、资产编号、网址或执行状态。逐屏个数必须精确匹配，编号唯一且比例一致，字段严格限定。最终展示文案中的数字及一组高风险宣传词必须能在原文找到；这不能证明所有自然语言声明真实，用户仍需逐屏核对，用户自述也不是认证事实。
视觉与逐屏阶段同时接收原始 brief（简报），保留用户要求的光线、背景、留白、风格和禁用内容；商品事实仍只取通过逐字溯源的 productFacts（商品事实）。每屏 purpose（用途）最多300个、copy（画面文案）最多4条且每条150个、prompt（画面提示词）最多1000个 UTF-16（字符串编码）单元；与后端接收合同使用同一计数和首尾空白规则。标题与文案均建议短中文，避免密集小字；商品瓶口、泵头、瓶盖、标签和比例保持一致。没有依据时不设计拆盖、剖面、爆炸图或改变结构的使用画面。
成品视觉描述、一致性说明、逐屏标题、画面文案和提示词如包含“品牌待确认”“容量待确认”“价格待补充”“售后待补充”“价格售后待补充”“价格/售后待补充”“参数待填”“参考图待确认”“待确认商品”，立即返回 DETAIL_PAGE_INTERNAL_PLACEHOLDER（内部占位文字错误）。这些提醒可保留在未知项，不能进入成品；不会自动删除文字、重发模型请求或改写事实。
响应只接受成功状态、单个 JSON（结构化数据）对象或完整单个代码围栏；拒绝重复键、截断、额外字段、数量错误和未知版本。错误只输出固定代码，不回显简报、响应体或密钥。无图像、联网、文件读取或工具调用的 Python 节点可独立零模型测试。
供应商非200响应在读取响应体前终止，固定区分 FACTS（事实提取）、VISUAL（视觉规范）、SCREENS（逐屏策划）三个阶段。错误格式为 DETAIL_PAGE_<阶段>_HTTP_<状态>，状态只允许400、401、403、404、408、409、422、429、500、502、503、504，其余统一 OTHER（其他）；不拼入供应商错误原文。未指定固定阶段时保留旧 DETAIL_PAGE_RESPONSE_STATUS_INVALID（响应状态错误）兼容。503等错误不会触发节点自动重试，也不会重跑前面已完成的模型请求。

可靠回传
详情页 API（接口）采用 Dify 事件流。在 workflow_started（工作流开始）后，执行器在持租和围栏校验下立即保存运行编号，仍完整消费流，不主动断开。连接丢失后或重启后只查询 GET /workflows/run/{id}（原运行详情），不重复提交；成功、失败、停止均回传本机。没有拿到运行编号的中断保留待核对，不能假定未收费。事件流总限600秒，长期运行另受执行器30分钟查询暂停限制。旧调用继续使用阻塞合同。

构建与原应用覆盖
在 platform（应用目录）执行 node workflows/dify/detail-page-v1/build.mjs，可重建公开包。
追加 --overlay <不含秘密值的旧导出YAML> <var内输出目录> 可生成仅供原应用覆盖的私有包。它保留原环境变量编号，将秘密变量替换为 [__HIDDEN__]（保持原值哨兵），不读取或写入真实密钥。该私有包不能用于新建应用；公开包的空值也不能直接覆盖有密钥的草稿，否则会清空配置。
覆盖前备份；覆盖后核对环境变量掩码仍有值、新旧分支、输入/输出和禁重试设置，单独运行代码节点零模型校验后再发布。导入草稿不等于已发布；不要以导入成功代替模型与本机端到端验收。

失败与回归记录
首版离线108项通过，但云端导入草稿后检查清单报2项错误：两条分支各有结束节点，重复声明 plan_json（输出变量）。该离线验证遗漏了跨结束节点变量唯一性，不能据此宣称云端可发布。已改为变量聚合器加唯一结束节点，保留旧输出名称，并新增检查入口、两条聚合输入、唯一出口及连线的回归。实际云端发布/运行结果由本轮部署验收另行记录。

随后真实执行中三个模型节点均成功，事实与视觉阶段各返回7条未知项，表述不同，合并14条却被原最终12条上限拒绝。这是本地合同设计缺陷，不是模型失败。现将最终未知项上限修为两阶段总上限24，单阶段仍12；补充7+7、12+12、稳定精确去重及单阶段13项拒绝回归。未增加模型请求或令牌预算。已有三个模型输出可仅重新运行最终纯校验节点，不应重复执行模型节点；单节点成功不自动改变原失败工作流的终态，采用已有结果必须保留其来源和本地校验记录，不能冒称原运行成功。

本轮继续发现并修复三类确定性缺陷：节点与提示词原先允许用途500字、6条各200字文案、提示词1200字，超过后端上限；Python（代码节点）与 JavaScript（后端）对表情字符和空白的计数不同，且编号校验后未回写去空白值；原始简报中的视觉约束未传入后两阶段。新增回归先对旧包运行，39项中10项失败；更新源文件并重建包后，节点与适配器合同共104项通过，包含2、6、10屏边界、成品占位拦截和未知项保留。原真实失败输入经最新纯节点回放得到6屏、14条未知项，并通过后端接收合同；这只证明既有模型输出可被正确接收，不代表重新执行了云端模型或已验收真实成图。
