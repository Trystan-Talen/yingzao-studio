# 创作记忆与产品资料方案

日期：2026年11月13日。状态：方案已实施，本地审查及已列范围验收完成，见[交付记录](DELIVERY.md)。

## 判断与范围

长期复用方向成立，但不能把所有信息混成一个用户画像。项目已有品牌库、品牌引用与规划快照；缺失的是个人创作记忆、产品事实实体，以及用户可核对的本次引用记录。职业只作为自愿填写的创作背景，不推断个人特征，也不转为商品证据。

编码助手的设计只提供原则参考：[OpenAI（开放人工智能公司）官方文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)说明分层和作用域；[Claude Code（克劳德代码助手）官方文档](https://code.claude.com/docs/en/memory)区分显式规则与自动记忆，支持检查和编辑。它们不能证明本产品应自动收集画像。本轮采用明确保存、来源可见和按需选取。

## 信息模型

| 类别 | 保存位置 | 更新及时间规则 |
| --- | --- | --- |
| 职业、创作角色等稳定背景 | 当前用户、当前空间的私有记忆 | 同主题替换，保留版本号；不因时间自动变假 |
| 风格、语气等偏好 | 私有记忆 | 按确认时间衰减；默认90天半衰，低于四分之一停止默认带入；读取不刷新时间 |
| 活动需求等临时信息 | 默认留在单次任务；明确保存才成为临时记忆 | 必填截止时间，到期停用 |
| 品牌名称、视觉规范、描述 | 既有品牌库 | 沿用已有权限与管理流程 |
| 产品名称、事实、禁用宣称、参考图 | 新产品库，可关联品牌 | 显式修订与并发版本检查；可设有效期；私有品牌不通过共享产品泄露 |

时间衰减是复用权重，不是事实真实性概率。长期记录也可设截止时间。删除或停用影响后续新方案；历史已确认方案保留当时快照，界面明确说明。

## 创作闭环

1. 用户建立品牌／产品和自愿保存的记忆；可查看、搜索、编辑、停用、重新确认或删除。
2. 创作时明确关联产品／品牌；产品参考图片另行勾选。本次可关闭个人记忆。
3. 服务端按用户、空间、可见性、媒体类型和有效时间筛选。个人记忆最多8条、主题与正文合计6000字，按临时要求、创作偏好、长期背景排序；同主题优先当前媒体专属项。遗漏数量可见；事实资料超限报错，不静默截断。
4. 产品资料进入有来源编号的事实通道；个人记忆进入独立低优先级上下文。当前需求和补答优先，事实冲突需要澄清，资料内嵌指令不得提升权限。
5. 规划保存所用来源、版本、内容和结果；确认界面展示实际引用。补答和执行沿用原快照，新建方案读取新版，避免修改资料悄悄改变已确认创作。
6. 产物沿现有报价、执行、保存与下载流程完成。暂不增加向量数据库、自动推断画像、无界资料搜索或收费记忆提炼。

本轮接入单项图片与视频主创作链；独立工具、整套详情页及分组套图明确拒绝新关联字段。分组旧模块文案未经过逐项规划，不能与新知识上下文组合后冒充已确认约束；界面说明并保留原分组流程。

## 实施和验收

- 数据层：仅追加迁移；个人隔离、产品权限、时效、并发冲突、恢复和素材校验。
- 规划层：原生和工作流合同兼容；字段指纹、显式引用、偏好不可作为商品事实、确认快照和恢复。
- 界面：保留既有深色风格；管理、选择、关闭、来源预览与错误恢复，桌面和手机布局。
- 验收：新功能单元／接口回归、严格工程检查、隔离浏览器中完成创建资料→关联→规划→修改→旧方案稳定／新方案更新→模拟产物保存与下载。

只使用临时测试数据库和合成素材；不修改正式运行数据，不调用真实收费模型，不推送、合并或发布。当前目录不存在版本库元数据，无法创建开发分支，直接修改本地源码并记录变更证据。
