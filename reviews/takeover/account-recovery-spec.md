## 二、两条用户流程与共同规则

**设置本地密码。** 已通过谷歌登录的用户进入设置，在账户安全区看到“设置本地密码”；界面明确显示其现有账户邮箱，不接受另填收件人。用户明确点击发送后，向该邮箱投递一次性链接；在发起操作的有效账户会话中打开链接，输入两次新密码，成功后退出所有浏览器会话，回到正常登录。谷歌关联保留；重新用本地密码登录后，原有解除关联流程才允许继续。

**忘记密码。** 登录页进入恢复页面，提交邮箱。服务开启时，对存在的本地账户、不存在的邮箱、仅谷歌登录的账户和邮箱级限流均返回相同的 202（已受理）、正文和界面：“如果此邮箱可通过密码恢复，你将收到恢复邮件。”仅已启用本地密码的账户产生邮件；仅谷歌登录的用户使用既有谷歌登录后进入设置流程。收到链接后设置密码，成功后退出全部浏览器会话，再正常登录。申请本身不改变密码或禁用现有登录。

共同安全原则依据 [OWASP（开放式应用安全项目）的密码恢复指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)：统一存在性反馈、带期限的一次性随机令牌、独立通信渠道、成功后清理会话、正常重新登录。这些是安全约束；下列具体时限和接口是本项目提案。

- 复用 12–128 字符的现有密码规则，服务端校验两次输入一致；拒绝多余字段，不接收用户标识、密码摘要或任意跳转地址。
- 令牌使用现有密码学随机函数生成 32 字节，数据库只存 SHA-256（摘要），默认 30 分钟有效。明文令牌仅在进程构造链接时及尚待投递的加密邮件正文中存在。
- 链接由固定公共源地址生成，形式为 `/password/reset#token=...`（密码恢复页面及片段令牌）；不信任请求主机头，不将令牌放进查询参数或日志。生产环境使用加密连接；页面不加载外部资源，设置禁止缓存和不发送引用来源的策略。打开、预览或邮件扫描链接不会消费令牌；提交新密码才消费。
- 设置本地密码的令牌还绑定发起会话摘要。消费时重新校验相同用户、原会话仍有效且尚无本地密码；在其他浏览器打开时明确引导回发起浏览器或重新登录并发起，不能悄悄降级成无会话恢复。
- 新请求不作废尚有效的旧链接，避免攻击者仅靠再次申请就使用户邮件失效。一次成功消费使该用户全部未完成链接失效；并发消费只允许一次成功。
- 请求处理不等待邮件网络发送。先在同一事务保存令牌和加密队列，提交后返回；成功后另入队一封不含密码/令牌的安全通知。
- 公共恢复接口不返回账号、投递记录或令牌；已登录用户只能查看自己的设置状态。工作空间管理员的权限不包含他人的账户恢复记录。
- 所有浏览器会话含当前会话一并撤销，清理浏览器会话凭据，不自动创建新登录。现有应用编程接口密钥是独立凭据；本提案不把“密码重置”写成“被盗账户全部凭据恢复”。成功页应链接到既有密钥管理页供审查/撤销；如原站或安全验收要求自动撤销密钥，须补入明确规则和用户提示后实施。

## 三、最小接口与明确关闭状态

以下接口名称为提案，均位于 `/api/v1/auth/password`（账户密码接口）下。新增共享运行时合同，响应继续使用现有数据/错误包装。

| 接口 | 身份要求 | 输入与输出 |
|---|---|---|
| `GET /status`（读取状态） | 可匿名；账户细节仅有效网页会话 | 匿名只返回全局开关和关闭原因；会话可返回本地密码是否启用、是否可发起设置及脱敏目标邮箱。应用编程接口密钥不能取得个人安全详情。 |
| `POST /forgot`（申请恢复） | 匿名，同源网页请求 | 只接收邮箱；开启时固定 202（已受理）。关闭时对所有有效邮箱统一 503（服务未启用），在查询账号前返回。 |
| `POST /setup-request`（申请设置本地密码） | 有效网页会话、同源；尚无本地密码且已有谷歌身份 | 不接收邮箱。重新读用户表，从固定账户邮箱入队；已设置、无身份或失效会话明确拒绝。 |
| `POST /complete`（提交新密码） | 恢复凭令牌；设置另需绑定会话 | 只接收令牌、新密码、确认密码。服务器从令牌记录决定用途。非法、过期、已用、已撤销统一报“链接已失效，请重新申请”，不透露用户。成功返回已变更状态并清理会话凭据。 |

恢复开关建议新增 `PASSWORD_RECOVERY_ENABLED`（密码恢复启用配置），默认关闭；必须与有效邮件传输配置同时显式开启。只配置已有通知发信账号不自动扩大到恢复邮件。界面明确显示“此实例尚未启用邮件密码恢复”，不会伪造验证码或声称已发送。配置不完整时启动明确失败，避免开启状态与实际能力矛盾。真实发送仍须在本轮获得明确授权后才做外部联调；开发和自动化只用隔离的本机收件服务器。

新增接口复用现有[来源校验](../../platform/src/server/app.ts#L107)，并要求发起网页写入提供精确同源来源；拒绝跨站和应用编程接口密钥代替会话。补充日志字段脱敏：令牌、新密码、确认密码、邮件正文和链接；错误结构不得回显输入。

限流建议：每个网络来源 10 次/15 分钟；规范化邮箱使用带密钥摘要存储限流键，每邮箱每 60 秒最多新建一封、每小时最多三封。邮箱级命中仍返回统一受理状态；网络来源级命中对所有邮箱统一拒绝。计数应写入 SQLite（数据库），保证重启及多接口进程一致。对未知邮箱也走相同计数和令牌生成路径，无网络调用和存在性提前返回；设置统一响应最短完成时间并测量分布，不能把随机等待当成唯一防枚举保障。

## 四、追加迁移与服务边界

不改写已应用的 0016–0018 迁移。实施时追加下一个未占用编号，至少包含：

| 数据对象 | 关键字段与约束 |
|---|---|
| 用户凭据修订号 | 在用户表追加非负整数，默认 0；每次成功设置/恢复递增。旧用户密码和本地密码启用标志保持原值。 |
| 密码请求表 | 主键、用户外键、用途（恢复/设置）、唯一令牌摘要、固定邮箱快照、凭据修订号、设置场景的会话摘要、创建/过期/消费/撤销时间；用途与会话是否为空有检查约束。索引覆盖用户的有效请求和到期清理。 |
| 账户邮件队列 | 用户外键、请求外键、唯一事件键、请求/变更通知类型、密文、投递状态、尝试数、租约、下一次尝试、固定错误码及时间。没有工作空间归属，也不暴露给空间邮件列表。 |
| 恢复请求限流桶 | 带密钥摘要的邮箱/网络来源键、用途、时间窗、计数、过期时间；唯一键保证事务内更新，定期清理，不存未知邮箱明文。 |

选用独立的**账户数据归属**来避免为一封恢复邮件伪造工作空间、受团队成员变动影响或泄漏给空间管理员。复用同一邮件传输进程、加密格式、错误分类和重试算法；将既有投递进程所需的领取/续租/完成接口提取成小的队列合同，供工作空间与账户两个数据源使用。无需重建现有邮件表、放宽其事件约束或另引入消息中间件。

账户邮件的附加认证数据绑定队列域、记录编号、用户和唯一事件键，防止把密文挪给另一个用户或另一队列；保留现有工作空间邮件的认证数据规则，不使历史密文无法解密。

领取账户邮件前检查用户邮箱快照、凭据修订号和请求状态；过期、已消费、撤销或失去绑定会话时取消并清除正文。请求完成/到期时清除待投递密文；发送中的旧邮件即使已被传输层接受，其链接也必须无效。沿用既有“不明接受结果不自动重发”的策略，不将网络超时认作未发送。

完成操作先在事务外计算新密码派生值，再进入立即写事务，重新核查所有条件，原子消费令牌、更新密码与本地密码标志、递增修订号、撤销全部会话及其他请求、取消过期请求邮件、记录消费时间并入队安全通知。失败时整体回滚；数据库事务不包含邮件网络或密码派生计算。不要先消费令牌再等待昂贵操作。

还须修正即将由新功能引入的竞争条件：[当前密码登录](../../platform/src/server/core/auth.ts#L230)在异步比较后直接创建会话。实施恢复后，登录必须在发会话的事务内重查初始凭据修订号，否则旧密码比较开始后发生重置，仍可能发出新会话。现有谷歌解绑的会话复查和唯一登录保护继续生效。

账户请求的消费记录形成不含明文秘密的持久完成证据；运行日志只写固定事件、请求编号、结果和撤销数量，不借用空间审计来暴露账户信息。恢复不更改用户身份、空间成员、谷歌主体关联或项目归属。

## 五、可执行验收

| 编号 | 前提与动作 | 必须观察到的结果 |
|---|---|---|
| 账户 01 | 邮件或恢复开关关闭，打开登录/设置并申请 | 页面明确关闭；接口统一未启用；没有令牌记录、队列记录、网络发送或演示成功提示。 |

| 账户 03 | 已登录用户点击设置，经本机邮件链接提交两次密码 | 目标邮箱不能改；一次消费后标志启用、谷歌身份保留、全部旧会话失败，新密码可正常登录；再以当前密码确认才可解绑。 |
| 账户 04 | 设置链接在其他用户、其他会话、已退出/过期会话中提交 | 全部拒绝且不消费合法请求；用户回到原有效会话仍能继续。 |
| 账户 05 | 分别提交已知本地邮箱、未知邮箱、仅谷歌邮箱、被邮箱限流地址 | 状态码、响应结构、可见文案一致；只有合格本地账户产生队列；计时样本无账号分支提前返回。 |
| 账户 06 | 申请恢复后先继续用旧密码登录；再合法完成恢复 | 申请阶段旧密码仍有效；完成后旧密码和全部旧会话失效，新密码有效，身份/空间/资产不变；没有自动登录。 |
| 账户 07 | 错误/过期/撤销/已消费令牌、两次密码不一致、短密码、额外用户标识 | 不改变密码；无跨账户结果；非法表单不消耗原本合法令牌。 |
| 账户 08 | 两连接同时提交同一或同修订号的不同令牌 | 只有一个事务成功；最终只有一套新凭据；变更通知的唯一事件只出现一次。 |
| 账户 09 | 控制旧密码比较暂停，另连接完成恢复，再继续登录 | 旧比较不能在恢复后发出有效新会话。设置请求与解绑/退出竞争也重新检查会话。 |
| 账户 10 | 重启接口/工作进程、邮件临时拒绝、明确永久拒绝、发送结果未知 | 队列和有效期保留；有界重试；未知接受状态不盲发；过期后不再发送可用链接，密文被清理。 |
| 账户 11 | 空间管理员、其他用户、应用编程接口密钥请求账户状态/完成接口 | 无权查看他人恢复详情或代替网页会话；空间邮件接口不返回账户队列。 |
| 账户 12 | 打开邮件、刷新、返回、重复点击、手机宽度及键盘操作 | 查看不会消费；错误能定位，提交只执行一次；敏感字段清理，成功回正常登录，不留下包含令牌的成功地址。 |
| 账户 13 | 旧库副本升级并恢复，新库迁移，两个进程并发启动 | 旧迁移摘要未变；旧密码/身份/会话字段保持；新约束有效；已有邀请、通知与工单投递回归通过。 |

第二条将测试浏览器保存在项目私有目录；现阶段只安装 Chromium（浏览器）。先覆盖桌面 1440、笔记本 1280、平板 768、手机约 390 像素宽度的核心任务；后续关键流程再加入 WebKit（浏览器引擎）项目，不能把改变视口说成实测了所有设备和浏览器。

最少新增一个配置文件、一个隔离运行器和业务用例目录：

- `playwright.config.ts`（浏览器测试配置）：测试目录独立于现有模块测试，文件用 `.spec.ts`（浏览器用例后缀）；初期单工作进程、零重试，防止掩盖间歇失败；失败保留执行轨迹、截图和视频，报告、产物放在每次运行唯一的私有目录。将此配置纳入类型检查。
- `scripts/e2e.ts`（端到端隔离运行器）：创建唯一临时数据库/媒体/日志目录与回环端口，显式传递数据路径、随机测试密钥和媒体命令路径，关闭所有外部供应商、支付和真实邮件配置；启动实际构建接口与独立工作进程，等待健康状态，最后只停止自己创建的进程。不得复用现有服务或调用强制演示路径并播种的 `dev:demo`（演示启动命令）。保留失败数据供诊断，成功时清理临时数据。
- `tests/e2e/`（浏览器用例）：已新增 `test:e2e`（端到端测试命令）调用上述运行器，先构建并报告证据目录，依赖和锁文件已固定。当前实际覆盖桌面1440与手机390像素，未覆盖本节提出的其他尺寸或其他浏览器引擎。

首组用例必须包含真实界面提交、请求结果及持久化断言：空库注册 → 上传真实文件 → 创建项目 → 本机真实图像处理 → 检查产物尺寸/格式及归属 → 编辑保存/下载 → 刷新并重启后找回；另有视频裁剪及实际时长、拖拽/粘贴、断网重试、跨空间/角色隔离。测试额度通过仅指向临时数据库的既有额度服务构造夹具，不能改真实库或假造任务成功。

普通业务套件运行实际生产构建。账户恢复套件另用测试专用运行入口调用同一应用工厂和任务/邮件进程，显式注入仅本机收件配置并捕获真实协议邮件；这是应用依赖注入测试，不能冒充生产邮件传输联调。浏览器从捕获的测试邮件打开链接；生产环境仍禁止非加密邮件配置，不能为测试新增线上取令牌调试接口。仅谷歌账户可用受控身份和会话夹具开始设置流程，但该夹具不能证明谷歌外部登录已验证。浏览器网络日志应检查失败请求、控制台错误与重复提交；数据库和导出文件的业务断言才是通过依据。
