# 第一切片：创作恢复与可靠提交

版本日期：2026-10-16。状态：待实现；本文件将已确认问题转为可执行设计假设与验收标准，不能作为通过证据。问题来源：`baseline/client-audit.md` 的 C01–C04、C07–C08。主代理完成修改前浏览器基线后才开始业务代码修改。

## 目标与边界

用户从灵感、首页或项目进入创作；修改提示、素材和参数；查看任务再回来或刷新后继续；提交响应丢失时找到原任务；所有新首页媒体任务有项目归属。既有 SQLite（轻量数据库）记录、任务编号、已应用迁移、素材原件与画布版本均保留。

此切片不改变供应商调用、额度计算、任务子项、画布版本规则或付费授权规则。人工智能设计方案结构由独立切片实现，其采用动作应通过表单受控更新进入同一草稿保存机制。

## 数据与兼容

| 对象 | 保存位置和字段 | 兼容规则 |
| --- | --- | --- |
| 本机创作草稿 | 浏览器持久存储，键含版本、当前用户编号、空间编号、项目编号；无项目使用“新创作”键。值含版本、更新时间、当前图片／视频类型、完整输入、显式未保存状态及可恢复的素材编号。 | 仅保存文本、参数、素材编号；不保存令牌、密钥、带权限的媒体地址或文件二进制。读取做运行时校验，损坏数据提示并允许清除。不能读取其他用户／空间草稿。 |
| 项目已保存草稿 | 沿用现有项目消息中的 `metadata.draft`（草稿元数据）和 `JobInput`（任务输入）合同。 | 不改旧消息、不迁移数据库。媒体表单只恢复 `image.generate`（图片生成）与 `video.generate`（视频生成）；工具草稿独立找入口；`text.assist`（文本辅助）仅属辅助记录。 |
| 参考素材 | 草稿保存编号，实际元数据经当前空间权限逐项读取。 | 不因一次读取失败从输入删除编号；无权限／已删除与临时网络错误分别提示。允许用户明确移除失效引用。 |
| 已确认待提交请求 | 浏览器持久存储，键隔离用户／空间，值为请求编号、报价编号与快照、完整输入、原入口／项目、确认时间、状态。 | 在首次网络提交前保存；记录不可因重新渲染、输入变化、刷新、弹窗关闭而自动换编号。已提交后清除在途记录或保留任务定位信息；不能依赖未确认的新报价代替旧请求。 |
| 项目任务页 | 现有 `/jobs`（任务接口）的项目、页码和页大小参数。 | 服务端分页合同不变；不能把任务分页和消息分页共用一个页码。 |

本机存储不可用或写入失败必须显示“当前修改仅保留在此页面”，保存草稿入口仍可用。后台存储失败不应吞掉、也不应误报已保存到项目。浏览器持久存储只保证同浏览器恢复；跨设备以显式保存到项目的服务器草稿为准。

## 草稿状态机与读取优先级

状态：读取中 → 可编辑／恢复受阻 → 本机已保存 → 保存到项目中 → 项目已保存；写入失败进入保存失败。任何输入变更重新标记本机修改。画布状态与创作草稿状态分别显示。

1. 先确定用户、空间、项目，再读取本机草稿；项目消息未完成前不可用空值覆盖持久化记录。
2. 有本机尚未提交／未显式丢弃的修改时优先恢复本机草稿；服务器新消息不能覆盖正在编辑的草稿。若检测到服务器比本机基准更新，显示恢复选择，保留两份输入直到用户选择。
3. 没有本机修改时恢复最新媒体草稿；辅助任务不参与媒体草稿选择。若只存在工具草稿，可显示工具入口，同时媒体表单保留项目描述默认值。
4. 图片／视频可各保存一份当前表单，切换类型不能丢失另一类型已填参数；不支持参数必须说明调整，不能静默删素材。
5. 切换“创作／会话与任务”保留同一表单状态；即使卸载，恢复键也必须稳定。刷新、浏览器返回、页面导航、退出再登录后按隔离键恢复。
6. 手动“保存草稿”沿用服务器消息持久化。成功后更新本机基准与保存提示；失败保留全部本机输入。空提示但有素材／参数修改允许保存；生成仍遵守原必填规则。
7. 当前文档编号与版本是提交瞬间的画布上下文，不能盲用本机旧版本覆盖工作台当前版本。用户输入与画布版本分别管理。

## 素材恢复状态机

每个编号独立进入：待读取 → 读取中 → 可用／临时失败／不可用。主参考、额外参考和物料模块参考都必须覆盖；同编号跨组复用不改变原输入顺序，首尾帧重复编号必须保留两处。

- 读取中展示已有素材和剩余数量，开始创作及报价入口禁用，并说明“正在恢复参考素材”。
- 临时失败保留编号，显示重试；一次失败不能清空已恢复的其他素材。
- 不可用显示可识别名称或编号末尾及具体原因，提供移除。只有用户确认移除后才能从草稿和引用文本中删除；沿用已有引用移除确认。
- 一切可用后，提交引用编号与恢复前一致；失败和空选择必须可区分。不要把“恢复失败”表示为空素材数组。
- 上传中追加文件不得无反馈：允许加入队列或明确提示完成后重试。已入库素材不因页面刷新而重复上传；原始未完成文件如没有持久化二进制，明确要求重新选择，不能承诺断点续传。

## 提交状态机与幂等

状态：编辑 → 请求报价 → 待确认 → 已确认持久化 → 提交中 → 已找到任务；网络失败进入结果待核对。只在确认前允许放弃报价；已确认请求应先核对结果。

1. 报价绑定原输入快照，确认后先持久化原请求，再调用现有提交接口。快照有任何变化都不能复用旧请求编号提交新内容。
2. 恢复页面遇到在途请求时显示请求时间、项目和“核对提交结果”，先执行只读查找。恢复不是重新调用供应商。
3. 建议追加 `GET /jobs/by-request/:requestId`（按客户端请求编号查询任务）：只查当前用户、空间及现有读取权限，返回现有任务对象或明确的未找到；其他用户的编号不能泄露存在性。无需数据库迁移，使用已有请求编号列。
4. 查到任务即显示同一任务结果，并定位项目；不重新报价，不重新扣费，清理对应在途记录。
5. 查不到任务只表示本次查询尚未见记录。不得自动产生新编号；允许用户明确“继续提交原请求”，向原提交接口重放完全相同的输入、报价编号和请求编号。现有服务端在报价校验前先查幂等记录，因此即使报价已过期，已经创建的任务仍可找回。
6. 若原请求返回报价过期且未创建任务，保留草稿，清晰提示重新报价。用户重新确认后才生成新提交；不能在背景静默换报价或无限重试。
7. 核对失败或网络不可用时保留在途记录及输入；继续编辑可产生新草稿，但旧提交身份仍可核对。所有恢复调用固定原空间编号，不能使用切换后的全局空间。
8. 本机有多个入口的在途请求时按请求编号保留列表，不能用一个覆盖另一个。辅助任务和媒体任务需各自匹配，禁止媒体表单找回辅助任务后误导航。

## 首页提交归属与项目任务分页

- 首页媒体表单先落实项目与草稿，再估价；创建出的项目编号写回本机记录。后续估价失败、关闭报价、提交响应丢失或刷新都继续使用同一项目，不能重复建立空项目。
- 创建项目成功但保存草稿失败时保留已获项目编号、提示重试；不得再次创建项目。此处无需回滚或删除用户项目。
- 灵感复用继续使用现有项目创建路径。素材、提示、可支持参数进入该项目草稿；新逻辑不得再创建第二个项目。
- 提交成功展示当前任务与项目入口；进入项目即可看到状态、产物、下载和画布后续操作。
- 项目任务与会话分别分页；切换项目重置页码。超过一页时显示总数、当前页及上一页／下一页；查询错误显示重试，不伪装成空状态。新任务提交后显示任务第一页或直接定位新任务。

## 验收用例

| 编号 | 前置与操作 | 必须观察到的结果 | 证据 |
| --- | --- | --- | --- |
| R01 | 在项目填写提示、比例、数量、品牌、主／额外参考和物料模块；切换会话标签后返回，再刷新。 | 所有用户输入和顺序相同；无新增任务／额度变化；草稿与画布保存状态分开。 | 真实浏览器步骤、刷新前后字段快照、本机存储与数据库只读核对。 |
| R02 | 同一浏览器切换两个用户、两个空间、两个项目；各输入不同提示并恢复。 | 只恢复对应范围；无跨空间素材请求；失去权限时提示且不能提交。 | 自动化隔离测试与浏览器抽验。 |
| R03 | 图片草稿之后存在更晚的文本辅助、工具及系统消息，刷新项目。 | 图片草稿正确恢复；辅助任务仍在会话；不存在无效文本辅助工具入口。 | 真实 SQLite（轻量数据库）集成与浏览器。 |
| R04 | 三个素材中一个延迟、一个返回无权限、一个正常；另有首尾帧同编号两次。 | 正常素材可见，延迟／失败分别显示；提交禁用；重试或明确移除后可继续，重复首尾帧仍两项。 | 自动化请求控制、浏览器状态及提交请求快照。 |
| R05 | 提交到服务器成功后故意丢弃响应，刷新，核对原请求。 | 返回同一任务编号；任务和预留流水各只有一份；外部测试适配器执行一次。 | SQLite（轻量数据库）任务／额度断言、浏览器恢复操作。 |
| R06 | 首次提交未到服务器，刷新后继续提交原请求；随后报价过期再重试。 | 未过期时原编号只创建一次；过期且无任务时要求重新报价确认；不会自动新建。 | 接口集成与浏览器。 |
| R07 | 本机存储损坏、禁用或容量不足；继续输入并手动保存到项目。 | 页面不崩溃，显示恢复能力受限；服务器保存可用；不错误显示本机已保存。 | 存储异常单测与浏览器。 |
| R08 | 从首页开始媒体创作，关闭报价、刷新，再报价并提交。 | 仅一个项目，草稿完整，任务有项目编号；提交成功后结果入口可见。 | 数据库项目／任务计数与浏览器。 |
| R09 | 项目含 31 条以上任务，翻页、刷新、切换项目，再创建新任务。 | 能从原项目找到旧任务；与会话页码互不干扰；新任务可定位；空／错／加载状态明确。 | 真实分页接口与浏览器。 |
| R10 | 在 390、768、1000、1440 像素宽操作媒体切换、素材恢复提示和提交恢复。 | 关键操作可见可达；不会出现必须全页横向滚动才能确认的状态。 | 当前版本截图和真实操作记录。 |

禁止用付费模型调用构造这些故障。使用既有隔离测试环境、实际本地媒体工具或明确标注的测试适配器。自动化必须断言数据库与业务结果；浏览器测试不能只断言按钮存在。

## 实施分工与评审门

- 客户端切片：创作表单、工作台、提交组件、素材选择器及专用恢复状态模块。避免同时修改全局样式和人工智能方案显示。
- 服务端补充：按请求编号读取的权限接口及集成测试；不改旧库迁移。客户端采用该接口前需合同确认。
- 完成门：以上用例逐条记录实现状态、验证状态、阻塞原因；类型检查、规范检查、相关测试与构建通过；真实浏览器至少完成 R01、R03、R04、R05、R08、R09、R10。
- 尚未实现／未验证的上传二进制刷新续传、跨设备未保存草稿同步、真实模型效果继续留在完整范围台账，不能在本切片完成时宣称全功能完成。
