# 后端与代码质量审查

日期：2026年11月13日。结论仅覆盖下列当前源码检查与隔离回归；未使用真实凭据发起外部请求，也未修改正式运行数据。没有直接读取或输出凭据，但旧测试配置存在隐式加载本机环境文件的路径，不能声称全程没有读取；本轮已用合成配置复现并补齐隔离。

## 已修复

1. **高优先级：集合修改会丢失未出现在列表中的关联。** 前端原先从“未删除素材”列表拼出整个集合，再全量覆盖；加入或移出一个素材会清除回收站素材的集合关系，两个客户端的独立添加也会互相覆盖。新增事务内的 `PATCH`（局部更新）集合接口，只添加或移除明确指定的素材；保留旧 `PUT`（全量替换）接口兼容。重复操作不产生重复关联，移出支持回收站素材，全部目标校验完成后才写入。拒绝跨空间、无写权限、已删除集合、添加已删除素材及同一素材同时增删。独立复核发现初版增量接口遗漏既有500总成员限制，已补足事务内最终数量校验：包含回收站成员，达到上限后重复加入仍成功，等量替换可成功，超限整批回滚。

2. **中优先级：供应商请求错误时未释放响应资源。** 公用请求函数遇到鉴权失败、限流、服务器错误或声明超大响应时直接抛错，未取消尚未读取的响应体；成功、无效正文和中断响应也未释放读取器。现在拒绝的响应立即取消，读取器始终释放，清理异常不覆盖业务错误；已提交但结果不确定的标记保持。该修改不代表真实供应商效果验收。

3. **中优先级：最大长度工作流测试间歇性输入阻塞。** 初始全量测试和独立完整节点测试均出现10屏用例子进程超时；阶段追踪再次复现时仅记录到进程启动，卡在 `json.load(sys.stdin)`（读取标准输入并解析）阶段，尚未编译或执行工作流。正常同样输入的工作流校验约0.65–0.88毫秒，没有证据显示业务正则灾难回溯。测试辅助函数改用权限受限的临时文件描述符传入原样输入，执行后关闭并删除；测试体、工作流源码及10秒限制保持不变。

4. **中优先级：直接运行测试可能隐式读取本机环境配置。** 旧测试配置只提供媒体命令路径，构建工具自动加载环境文件、应用配置模块顶层加载环境文件两条路径都没有在测试配置中阻止。新增测试专用 `envDir: false`（禁用环境文件目录）及 `DOTENV_CONFIG_PATH`（环境文件路径）空设备设置，不改变正式运行配置。合成配置黑盒回归在修复前确认普通凭据哨兵和前端环境哨兵均被加载，修复后均未加载；测试只导入配置模块，不以默认路径创建运行数据。该修改不负责清除调用进程预先导出的凭据，完整子进程隔离仍使用现有白名单启动助手。
