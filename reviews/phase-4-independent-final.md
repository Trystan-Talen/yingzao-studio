## 可复现缺陷

### R1 / P1：UI 生成不透明遮罩，与 OpenAI 的透明编辑区协议冲突

原 `src/web/components/MaskEditor.tsx` 在输出 canvas 全画黑底再叠白色笔画，PNG alpha 全为 255。`providers/openai.ts` 正确要求有效透明编辑区并拒绝 alpha min=255，导致通过 UI 画出的遮罩全部无法推理。这不是缺密钥问题。

已检查前端修复代码：白色笔画仍用于用户预览，导出使用 `destination-out` 得到透明编辑区，并扫描实际绘制 alpha 拒绝空图。OpenAI 校验应保留；Flyelep 黑白 mask 需要独立转换，根代理处理中。应新增“实际 UI 导出 PNG → provider 读原件”的边界回归，不只构造手工 fixture。

### R2 / P2：AI 助手重开会继续使用旧 prompt

原 `AIWriter.tsx` 常驻组件以 `useState(prompt)` 初始化一次。用户关闭助手、在 Composer 修改需求再打开，显示旧需求且可能按旧需求生成。已检查修复：`wasOpen` 检测 false→true 同步当前 prompt，清旧 jobId；打开期间输入变化不持续覆盖用户编辑。代码复评通过，真实浏览器新旧需求切换仍待最后 UI 回归。

### R3 / P2：局部设计模块的 @ 输入序号与实际请求不一致

原 `service.snapshot` 在 `splitItems` 前按全局参考列表替换 @ 序号。模块专有图片会改变真实数组，提示词可指向错误图片。最新代码改为 split 后逐 part 补全授权引用、按该项去重序列映射，文档先转为“参考文档”避免冒充图序号；OpenAI 请求亦去重。静态复评通过，等待根新增 quote/分模块合同回归。

### R4 / P2：本机图片 resize / stitch 在像素预算检查前分配输出

合法瘦长原图可经单边 width=8192 放大为远超内存预算的结果；原 stitch 也在全部 `.toBuffer()` 后才检查。不能依赖输入64MP限制来约束输出。

本独立代理已直接修复 `providers/local.ts`：读取 EXIF 后的方向尺寸，按 inside-fit 保守预估像素；任一边超过16384或面积超过64MP立即拒绝。拼接先完整预检累计高度，再渲染任何片段；该限制与最终素材入库单边上限一致。删除未识别操作落入普通转换的后门默认分支。

`tests/local-provider.test.ts` 7/7 实测通过：瘦长放大拒绝、面积限制、拼接累计限制、PNG/JPEG/WebP实物尺寸、EXIF旋转、正常拼接、移除的AI融合alias拒绝。未为了测试实际分配超大图片。

### R5 / P2：视频超分显示目标分辨率而实际请求仅接受倍率

原 `AdvancedTools` 在模型没有 resolutions 时添加1080p/4K选项；RealESRGAN adapter只发送scale。已检查前端作者修复为倍率与预计输出尺寸；官方允许 scale 1–8，本地2/4/8可保留。字幕去除无适配时应显示未接入，不能一直显示“正在加载能力”。
