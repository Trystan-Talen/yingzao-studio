# 项目与代码质量整改

日期：2026年11月14日。**本轮已复现问题完成修复，最终统一质量检查与关联浏览器验收通过。** 保持现有技术栈、深色风格和业务流程，没有数据库迁移或新增依赖。

## 修复结果

| 领域 | 复现的问题 | 当前行为 |
| --- | --- | --- |
| 品牌编辑 | 保存响应迟到时丢弃用户继续输入的内容；旧表单覆盖其他人刚保存的字段 | 区分提交快照和当前草稿，保留后续输入并继续更新同一品牌；网页必带读取版本，冲突时明确载入或合并 |
| 品牌并发 | 同一毫秒内的修改难以区分，删除读写未与版本变更串在同一事务 | 更新、删除、恢复的时间标识严格递增，相关读写在同一写事务；旧调用不带条件时保留兼容行为 |
| 任务执行器 | 初始化异常跑出统一收尾，图片读取无关视频密钥；任务留在执行中、额度仍被预留 | 初始化进入异常边界，仅读取当前步骤需要的连接；尚未外呼的失败正确释放，未知付费状态继续核对 |
| 调度与停止 | 调度重叠提取文档，停止先于领取过程完成，数据库关闭后仍被访问 | 同一执行器调度不重入；停止等待提取、调度和执行收尾；跟踪清理不再产生未处理拒绝 |
| 本机处理 | 已确认的纯本机平移及恢复被无关损坏模型密钥阻断 | 本机步骤按已冻结方案执行，保留素材、权限、参数、归属与围栏校验，不需要模型凭据 |
| 测试入口 | 常用测试命令继承模型凭据、数据库路径和前端构建变量，旧隔离测试未覆盖此入口 | 默认入口清洗父环境，测试、浏览器和质量命令共用受控工具执行器，保留参数、失败码与中断码 |
| 检查工具中断 | 本轮共用工具独立复核发现：主进程先退出后，忽略终止信号的孙进程残留 | 类Unix系统在中断后清理剩余进程组，再结束停止流程；有先红后绿回归 |
| 运维脚本 | 未指定库的兑换码命令写默认库；健康检查生成本机密钥，地址与等待边界不完整 | 兑换码先要求非空显式路径；健康检查只读地址／端口，支持网络地址规范化及5秒超时，帮助不初始化应用 |

品牌并发通过可选 `expectedUpdatedAt`（预期修改时间）实现，不改数据库结构。网页启用版本检查；旧接口客户端仍可不带该字段，其盲写行为没有被伪称为强制乐观锁。产品和记忆复用原有冲突恢复组件，字段展示分别适配。

失败与回归证据：[品牌编辑](evidence/brand-editor-validation.json)、[品牌写事务](evidence/brand-transaction-validation.json)、[任务复现](evidence/worker-red-reproduction.json)、[任务修复](evidence/worker-validation.json)、[父环境隔离](evidence/test-launcher-validation.json)、[进程组清理](evidence/tool-group-validation.json)、[运维入口](evidence/operations-scripts-validation.json)。

## 可执行的维护规范

新增[工程质量规范](../../platform/QUALITY.md)与编辑器格式约定，更新两级项目说明。规范覆盖模块职责、事务和异步边界、编辑冲突、付费未知状态、测试分层及交付证据。

- `pnpm quality:check`（开发质量检查）：严格类型、代码规范、格式、完整单元／集成检查，失败即停止。
- `pnpm quality:release`（构建质量检查）：追加隔离的前后端生产构建、本机处理资源和生产启动验证，记录每阶段结果；不代表部署，不包含浏览器验收。
- 规范检查新增静态跨层导入约束、显式类型导入、执行器基于类型的未处理异步检查，以及残留 `only`（仅运行指定测试）检查。编辑器测试可合法使用节点运行时；合法合同导入、测试夹具及规则拒绝都有回归。
- 格式检查补上此前遗漏的JavaScript（脚本语言）配置文件。常用检查不自动重装依赖，不读取本地环境文件，不继承供应商或运行库配置。

## 边界与后续维护

- 本轮没有付费模型、支付、邮件或短信外呼，没有执行正式运行数据写入、迁移、推送、合并或部署。已有真实模型样例仍按原记录的范围理解，本轮本机协议夹具不增加外部质量结论。
- 初始浏览器／监听沙箱拦截已与产品失败区分。旧健康帮助红测曾因忽略帮助参数向默认本地4310端口发出一次健康只读请求，不涉及业务读取或写入；之后改为专用临时端点重录，并验证新版帮助零请求。此经过保留在运维证据中。
- 进程组清理实测环境为macOS（苹果桌面系统）；Windows（视窗系统）仅处理直接子进程，不承诺整棵子进程树清理。
- 创作器、详情页工作室和执行器仍是需要逐步拆分的维护重点。本轮按已复现风险和清晰责任边界整改，不据文件行数或一次测试通过宣布架构、所有外部能力和所有历史分支均无问题。
